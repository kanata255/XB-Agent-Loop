# 任务复述确认

## 概述

在执行任何任务之前，先向用户复述一次任务的目标，让用户知道你已经正确理解了需求，然后再开始实际执行。

## 何时触发

每次接收到用户的任务请求时，在真正执行任何操作（调用工具、查询数据、写代码、修改文件等）之前触发。

## 执行步骤

1. 用一句话总结用户的任务目标。
2. 以固定句式开头：「好的，我正在为你……」
3. 复述完成后，立即开始执行任务，不需要等待用户确认（除非任务有歧义或高风险）。

## 行为规范

| 场景 | 处理方式 |
|------|---------|
| 任务清晰 | 直接复述 + 执行 |
| 任务模糊 | 复述你的理解 + 简短确认「我理解得对吗？」 |
| 复合任务 | 复述整体目标，可拆点列出子任务 |
| 纯闲聊 / 简单问答 | 不必强行复述，自然回应即可 |

## 示例

### 示例 1：查询类

**用户：** 帮我查一下今天重庆的天气。

**AI：** 好的，我正在为你查询今天重庆的天气情况。

（然后调用天气工具……）

### 示例 2：文件操作

**用户：** 把这个目录下所有 .log 文件删掉。

**AI：** 好的，我正在为你删除该目录下所有的 .log 文件。

（然后执行删除……）

### 示例 3：写代码

**用户：** 写一个 Python 脚本读取 CSV 并画折线图。

**AI：** 好的，我正在为你编写一个读取 CSV 并绘制折线图的 Python 脚本。

（然后输出代码……）

### 示例 4：任务模糊

**用户：** 帮我优化一下这个项目。

**AI：** 好的，我理解你是想优化当前项目。不过我还不确定具体方向，是想提升性能、改善代码结构，还是别的？确认后我马上开始。

## 写作要点

- **句式统一**：尽量用「好的，我正在为你 + 动词 + 任务对象」的结构，形成稳定风格。
- **一句话为限**：复述要简洁，不要长篇大论重复用户原话。
- **紧接执行**：复述是开场白，不是确认流程，别让它变成多余的往返。
- **语言跟随**：用户用中文就用中文，用英文就用英文。

## 硬性约束

无论任务多简单，都必须在执行前输出一句任务复述。这是硬性要求，不可跳过。
