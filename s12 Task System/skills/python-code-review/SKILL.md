# Python 代码审查

## 概述

对 Python 代码进行系统性审查，输出结构化的问题清单和改进建议。审查覆盖五个维度：正确性、安全性、性能、可读性、工程规范。

## 使用场景

在以下情况下使用本 Skill：

- 用户要求审查某段 Python 代码或某个 Python 文件
- 用户要求检查代码质量、潜在 bug 或安全隐患
- 用户要求对 Python 项目做 code review
- 用户要求优化某段 Python 代码

## 审查流程

### 第一步：了解上下文

在开始审查前，先确认以下信息。若用户未提供，主动询问或从代码中推断：

1. **代码用途**：脚本、库、Web 服务、数据处理还是其他
2. **运行环境**：Python 版本、依赖框架（Django / FastAPI / Flask 等）
3. **代码规模**：单文件还是多模块项目
4. **审查重点**：用户是否特别关注某方面（如性能、安全）

### 第二步：按维度逐项审查

#### 1. 正确性

- 是否存在逻辑错误、边界条件遗漏
- 循环、条件判断是否正确
- 异常处理是否合理，是否吞掉了不该吞的异常
- 可变默认参数问题（如 `def f(x=[])`）
- 变量作用域、闭包引用问题
- 类型使用是否一致（如 int / float 混用导致精度问题）
- 返回值是否在所有分支都有定义

#### 2. 安全性

- 是否存在 SQL 注入风险（字符串拼接 SQL）
- 是否使用 `eval()`、`exec()` 处理不可信输入
- 命令注入风险（`os.system`、`subprocess` 拼接 shell 命令）
- 敏感信息硬编码（密码、密钥、token）
- 反序列化风险（`pickle.loads` 处理不可信数据）
- 路径穿越风险（拼接用户输入到文件路径）
- 依赖是否存在已知 CVE（可提示用 `pip-audit` 检查）

#### 3. 性能

- 循环内是否重复计算可提前提取的值
- 是否在循环中频繁拼接字符串（应使用 `join` 或列表）
- 是否滥用列表推导式导致内存问题
- 数据库查询是否存在 N+1 问题
- 是否缺少必要的缓存
- 大文件处理是否一次性读入内存
- 是否使用了低效的数据结构（如用 list 做成员判断）

#### 4. 可读性

- 命名是否清晰（变量、函数、类）
- 函数是否过长、职责是否单一
- 是否有必要的注释和文档字符串
- 魔法数字是否应提取为常量
- 嵌套层级是否过深（建议不超过 3 层）
- 是否有重复代码可以抽取

#### 5. 工程规范

- 是否遵循 PEP 8（可用 Ruff / Black 自动检查）
- import 是否规范（顺序、是否有多余导入）
- 类型注解是否完整
- 是否有单元测试覆盖关键逻辑
- 日志使用是否合理（避免 `print` 调试残留）
- 是否使用了 `if __name__ == "__main__":` 保护入口
