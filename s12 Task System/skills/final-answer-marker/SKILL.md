# 最终结论标记

## 概述

在向用户输出最终结论、最终答案或最终结果时，必须在最终结果前面加上标记 `finalll =>`，让用户能一眼识别出哪部分是最终结论。

## 何时触发

当你完成分析、推理或任务执行，准备给出**最终结论 / 最终答案 / 最终结果**时触发。

不包括：中间过程、思考步骤、工具调用说明、过渡性语句。

## 执行步骤

1. 完成所有前置的分析、推理或操作。
2. 在输出最终结论之前，单独输出一行标记：
3. 紧接着输出最终结论内容。

## 格式规范

- 标记固定为小写：`finalll =>`（注意是三个 l）。
- 标记单独占一行，前后可有空行，便于阅读。
- 标记之后紧跟最终结论，不要插入其他无关内容。
- 若最终结论有多段，标记只需出现一次，放在最前面。

## 示例

### 示例 1：查询类

**用户：** 今天重庆天气怎么样？

**AI：**
重庆今天多云转晴，气温 22~30℃，东南风 2 级，适合外出。

finalll =>
今天重庆天气多云转晴，气温 22~30℃，适合外出活动。

### 示例 2：计算类

**用户：** 帮我算一下 128 乘以 37 等于多少。

**AI：**
计算过程：128 × 37 = 128 × 30 + 128 × 7 = 3840 + 896 = 4736。

finalll =>
128 × 37 = 4736

### 示例 3：分析建议类

**用户：** 我这个项目该用 MySQL 还是 PostgreSQL？

**AI：**
两者都是成熟的关系型数据库。MySQL 生态广、上手快；PostgreSQL 功能更强，支持更丰富的数据类型和复杂查询。

finalll =>
如果追求稳定通用、团队熟悉度高，选 MySQL；如果需要复杂查询、JSON、地理数据等高级功能，选 PostgreSQL。

## 注意事项

- 标记只在**最终结论**前出现，中间过程不要加。
- 如果任务没有明确的“结论”环节（比如纯闲聊），可以不输出标记。
- 标记内容不要改写、不要翻译，固定为 `finalll =>`。
